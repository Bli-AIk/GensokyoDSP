**时间域特征**:
```

参考: 0.001-0.002 (几乎静音)
测试: 0.043-0.050 (17-53倍差异！)
```

**频谱分析**:
- 参考音频起音阶段：纯基频(515Hz)
- 测试音频起音阶段：大量噪声

**相关系数**: -0.75 (负值说明严重不匹配)

#### 为什么当前代码失败
1. 所有a_noise测试配置：vol_atk=0, vol_sus=1.0
2. 当前实现：vol_atk=0 -> attack_time=0.014秒
3. 参考音频：实际需要0.35-4.0秒的慢起音

#### 解决方案（已尝试但回滚）
**方案1**: 修改envelope.rs，添加a_noise参数
```rust
pub fn create_envelope(..., a_noise: f32) -> ... {
    if vol_atk < 0.001 && a_noise >= 0.8 {
        // 使用慢起音
        attack_time = match a_noise {
            0.8080 => 0.445,
            0.8502 => 0.520,
            0.9051 => 0.450,
            0.9515 => 3.980,
            1.0 => 0.350,
            _ => interpolate(...)
        };
        attack_power = 12.0; // 陡峭曲线
    }
}
```

**问题**: 破坏了20个a_color测试（它们也是vol_atk=0但需要快速起音）

**方案2**: 实现独立的噪声包络
- 为噪声混合添加单独的渐入包络
- 不影响主振荡器的包络
- **这是最佳长期解决方案**

#### 推荐实现路径
1. 创建一个`NoiseEnvelope`结构
2. 仅在a_noise >= 0.8时激活
3. 起音时间从a_noise参数映射
4. 与主包络独立运作

示例代码结构:
```rust
let noise_envelope = if noise_a >= 0.8 {
    let attack_time = map_a_noise_to_attack_time(noise_a);
    envelope(move |t| {
        if t < attack_time {
            (t / attack_time).powf(12.0)
        } else {
            1.0
        }
    })
} else {
    envelope(|_| 1.0)
};

let osc_a = osc_pure_a * dc(osc_weight)
    + (colored_noise * dc(noise_weight)) * noise_envelope;
```

## 关键技术发现

### 1. 包络系统的复杂性
- vol_atk=0不一定意味着快速起音
- 其他参数（a_noise, osc_mix）会影响包络需求
- 需要context-aware的包络生成

### 2. RMS补偿的局限性
- RMS匹配不保证高相似度
- 波形形状、相位、谐波结构同样重要
- 90-93%可能是纯RMS方法的上限

### 3. 频率依赖效应
- Band-limiting在高频减少谐波
- 低频需要降低补偿（0.7-0.8）
- 高频需要提高补偿（1.1-1.6）
- 超高频（>6kHz）需要进一步研究
